# Pending proposal write observations

These test-only probes compile source copies based on `4c04b12` together with
synthetic aircraft, level, snapshot, setter, combat facade, terrain planner and
checkpoint. They do not run a real Minecraft world or MOD. A synthetic combat
callback changes the fake target after base control and formation proposal
creation. The probes distinguish the earlier base setter from a later pending
formation or combat setter, and do not retract earlier base or direct writes.

With Python 3, JDK 17, and a trusted ordered JSON array of existing **absolute**
mapped Minecraft/Forge and library classpath paths, run from the repository
root and choose an output directory that does not exist:

```sh
python3 ww-debug-benchmark/tools/inspect_pending_write_guard.py \
  --java-home /path/to/jdk17 --dependencies-json /path/to/classpath.json \
  --output /path/to/new-baseline-evidence
python3 ww-debug-benchmark/tools/inspect_pending_write_guard.py --guard \
  --java-home /path/to/jdk17 --dependencies-json /path/to/classpath.json \
  --output /path/to/new-guard-evidence
python3 ww-debug-benchmark/tools/inspect_pending_marker_policies.py --policy skip \
  --java-home /path/to/jdk17 --dependencies-json /path/to/classpath.json \
  --output /path/to/new-marker-evidence
python3 ww-debug-benchmark/tools/inspect_removed_pending_guard.py --policy removed \
  --java-home /path/to/jdk17 --dependencies-json /path/to/classpath.json \
  --output /path/to/new-removed-evidence
```

`inspect_pending_write_guard.py` without `--guard` compiles unmodified copies;
with the flag it modifies only the private copy's pending-write helper. The
unmodified baseline is expected to exit nonzero at the no-pending-setter
assertions for synthetic pilot/side changes. The guard copy suppresses those
pending setters but still returns/records the old authority. The later probes
compare an immutable local decision that returns player or NONE on rejection,
with marker updating or not updating; their switches are `--policy update` and
`--policy skip`. The removed probe has `--policy baseline` and `--policy removed`.
The latter additionally rejects a removed fake target and does not update the
marker on rejection. These are candidate observations, not merged features.

The marker probes pre-seed the UUID-keyed marker using a different synthetic
object with the same UUID. Skipping an update keeps that entry but makes it
potentially stale; updating may remove or overwrite it. A separate UUID marker
is also checked. Neither proves which live server owns a marker. Removed-with-mob
is an artificial callback condition, not a claim that it occurs naturally.
The returned authority and the existing marker never prove that a setter
succeeded or that the pre-callback base input was cancelled. `claimedWithoutProposal`
and direct writer controls retain existing behavior.

Each runner writes source copies, modified-copy patches when relevant, stubs,
class files, class-load logs, command exits, input/classpath hashes before and
after, and a runner snapshot. Preserve and inspect the **outer** exit separately;
a missing case, changed hash, unexpected class origin or unrelated failure is
inconclusive. Existing dependency paths are an external local prerequisite and
are not included in this repository. Hashes do not authenticate inputs or pin
the complete JDK/Python installation. The runners execute the `.py` file
directly, not the earlier generated bytecode cache, but do not pin the Python
standard library or its caches.

These tests do not establish real pilot takeover, a shared Minecraft client and
server state, `ReflectiveAircraft` native setter success, other direct writers,
removed entity reachability, same-mob replacement, reentry after a guard check,
concurrent mutation, or actual collision/terrain safety. The fake level ignores
AABBs and its clip always misses. A guard is a check at one point, not an atomic
ownership or effect guarantee. Run additional fixed-version real-MOD checks before
making behavioral or safety claims.

The latest removed-copy experiment treats removed or client as `NONE` even if
the fake pilot is a player; otherwise a rejected player is reported as
`PLAYER_CONTROLLED`. The earlier v1 copy reported `PLAYER_CONTROLLED` for the
synthetic removed-plus-player case. Both leave the old UUID marker untouched on
rejection. These are return-label choices, not proof of input ownership. The
fixture seeds the marker using a distinct UUID instance with the same value and
checks both `equals` and nonidentity; it also checks a different UUID holding
the same marker value. The normal claimed-without-proposal case starts with a
different marker and checks that the ordinary recorder updates it.

The removed-copy helper calls `ReflectiveAircraft.applyControl` only after its
gate; its boolean true means the adapter was called. The adapter has no success
result, and this probe uses a stand-in setter. It cannot prove that native
controls were applied. Public `applyControl(Entity):Authority` is unchanged in
the candidate source, but a full runtime or external-binary compatibility claim
would require separate verification.
