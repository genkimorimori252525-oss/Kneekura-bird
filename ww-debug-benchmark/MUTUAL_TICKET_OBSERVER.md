# Local reciprocal-dogfight force-loop observer

This read-only diagnostic is disabled unless `GameTestServer`, scenario `dogfight_mutual`, configured and actual primary A6M IDs, and exact property `wwdebug.mutualObserveTickets=true` all match. Gradle forwards `-PmutualObserveTickets=true` only to the GameTest server. `-PmutualObserveEntity=true` independently enables the existing entity observer. No diagnostic ticket, chunk request, private reflection, or new `getForcedChunks()` call is introduced. The original validation force loop still runs and has its existing side effects; the probe reads only views that loop already obtained, the validation's own tracking set, and the public `inEntityTickingRange` query. The original getter may itself lazily read SavedData and cache it; its existing call sequence is retained. Sampling and logging add CPU and I/O, so runs with the flag are distinct evidence.

After scene start and before completion, the END validation loop freezes the retained opponent reference's current chunk once, along with the exact primary center used for the 7×7 loop. It logs to the existing server logger at state changes and every 20 overworld ticks. Each log line has the server tick, primary/opponent UUIDs, frozen target chunk, reference identity/removed/level state, current reference chunk at finish, and `reference_at_end`. That label compares references within the loop only; it does not prove either is registered or ticking. The existing primary-tick entity observer has a different stage and may run before the opponent moves during that same tick. Join only by run, UUID, server tick **and chunk**, and do not assume the start-stage chunk equals the END chunk. Missing or inaccessible samples are unknown.

`owner_before/after` report membership in `ownedForcedChunks`, the validation's in-memory record of chunks for which it attempted an addition. It is not a real exclusive owner: the vanilla forced set is a global boolean, not reference-counted, and the existing code ignores the setter return when adding to that record. `target_in_request` says only whether the frozen target lies in this loop's 7×7 grid. `target_action` distinguishes not encountered, already forced, returned true/false, incomplete and unknown. An incomplete loop or diagnostic error is not a negative result.

`forced_first_read` is the target membership at the first existing forced-set read, and `forced_last_read_before_iteration_49` at the last existing read, immediately before that iteration's setter. They are the vanilla SavedData forced set only; Forge, player and other tickets need not appear. The views are sampled immediately, never retained as end-of-loop snapshots: an initially empty view may not follow a subsequently created SavedData set. The 49th setter or reentrant work may change the set after the last read, so `forced_after_loop` is explicitly `unknown`. A recorded setter return is not proof of what remains after other callbacks. `loop_complete=false`, a missing event, `probe_error=true`, or any unavailable value must be treated as unverified.

`range_before/after` are booleans read from the public ticking ticket range query for the **frozen** target chunk, before and after the existing loop. They are not the numeric tracker level, a record of other mods' ownership, or entity-section visibility. Queued tracker updates may be processed later. The other observer records the composite `isPositionEntityTicking` at a different point; even on the same tick and chunk, values can change between calls. When the range is false, composite false does not identify the visibility condition. No observer reads the private visibility map or numeric ticket level.

State-change timestamps are first-observed at these END sampling points, not exact engine transition times. The previous fingerprint is one bounded string per validation run; no chunk collection is copied. A scene can finish or disappear before END, or end with an exception or process termination, leaving no final sample. Existing writer buffering and server-log rotation can also hide output. Preserve each run's complete stdout, rotated logs, exit status, code and inputs; never overwrite a prior run. This diagnostic adds no persistent ticket and can be disabled by omitting the property or reverted with its commit. It does **not** change or repair the existing vanilla boolean ownership and cleanup semantics.
