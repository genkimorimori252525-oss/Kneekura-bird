# Local reciprocal-dogfight force-loop observer

This read-only diagnostic is disabled unless `GameTestServer`, scenario `dogfight_mutual`, configured and actual primary A6M IDs, and exact property `wwdebug.mutualObserveTickets=true` all match. Gradle forwards `-PmutualObserveTickets=true` only to the GameTest server. `-PmutualObserveEntity=true` independently enables the existing entity observer. No diagnostic ticket, chunk request, private reflection, or new `getForcedChunks()` call is introduced. The original validation force loop still runs and has its existing side effects; the probe reads only views that loop already obtained, the validation's own tracking set, and the public `inEntityTickingRange` query. The original getter may itself lazily read SavedData and cache it; its existing call sequence is retained. Sampling and logging add CPU and I/O, so runs with the flag are distinct evidence.

After scene start and before completion, the END validation loop freezes the retained opponent reference's current chunk once, along with the exact primary center used for the 7×7 loop. It logs to the existing server logger at state changes and every 20 overworld ticks. Each log line has the server tick, primary/opponent UUIDs, frozen target chunk, reference identity/removed/level state, current reference chunk at finish, and `reference_at_end`. That label compares references within the loop only; it does not prove either is registered or ticking. The existing primary-tick entity observer has a different stage and may run before the opponent moves during that same tick. Join only by run, UUID, server tick **and chunk**, and do not assume the start-stage chunk equals the END chunk. Missing or inaccessible samples are unknown.

`owner_before/after` report membership in `ownedForcedChunks`, the validation's in-memory record of chunks for which it attempted an addition. It is not a real exclusive owner: the vanilla forced set is a global boolean, not reference-counted, and the existing code ignores the setter return when adding to that record. `target_in_request` says only whether the frozen target lies in this loop's 7×7 grid. `target_action` distinguishes not encountered, already forced, returned true/false, incomplete and unknown. An incomplete loop or diagnostic error is not a negative result.

`forced_first_read` is the target membership at the first existing forced-set read, and `forced_last_read_before_iteration_49` at the last existing read, immediately before that iteration's setter. They are the vanilla SavedData forced set only; Forge, player and other tickets need not appear. The views are sampled immediately, never retained as end-of-loop snapshots: an initially empty view may not follow a subsequently created SavedData set. The 49th setter or reentrant work may change the set after the last read, so `forced_after_loop` is explicitly `unknown`. A recorded setter return is not proof of what remains after other callbacks. `loop_complete=false`, a missing event, `probe_error=true`, or any unavailable value must be treated as unverified.

`range_before/after` are booleans read from the public ticking ticket range query for the **frozen** target chunk, before and after the existing loop. They are not the numeric tracker level, a record of other mods' ownership, or entity-section visibility. Queued tracker updates may be processed later. The other observer records the composite `isPositionEntityTicking` at a different point; even on the same tick and chunk, values can change between calls. When the range is false, composite false does not identify the visibility condition. No observer reads the private visibility map or numeric ticket level.

## Optional same-position composite observation

For a separately versioned experiment, the additional exact flag `-PmutualObserveVisibility=true` enables extra fields only when `-PmutualObserveTickets=true` and the existing GameTest/A6M gate also succeeds. With the additional flag absent, no extra position or composite query is made and the previous END event format and change fingerprint are retained. This experiment does not change forced-set reads or ticket operations.

The observer first freezes the original cached chunk key and a separate immutable `reference.blockPosition()`. It records the block X/Y/Z and `block_chunk_matches`; if the packed X/Z chunk differs from the original key, the composite query and inferred visibility are `unknown`. Missing references, another level, access failures and missing timestamps are also unknown. The frozen reference may be stale, may move later in the tick, and is not evidence of actual entity registration. Minecraft's tested queries use X/Z chunk coordinates; Y is retained for provenance.

Immediately before the original loop, the observer reads the public range and then `isPositionEntityTicking` at that frozen block; it repeats the same order after the loop. The `before_query_tick`/`before_query_end_tick` and `after_query_tick`/`after_query_end_tick` values bracket each pair. Each composite result is recorded separately from the inference. Both queries only read current internal state in the inspected Forge version, but they are **not an atomic snapshot**. When both reads occur in the same nonnegative game tick, `range=true, composite=true` yields `true_if_stable`, and `range=true, composite=false` yields `false_if_stable`; both inferences require the state to have remained stable between calls. `range=false, composite=false` yields `unknown`; `range=false, composite=true` yields `changed_or_inconsistent`. A differing or unavailable bracket tick also yields `unknown`. None of these values proves that `Entity.tick()` executed, identifies another mod's ticket, or measures visibility at the earlier aircraft-tick observer.

The fingerprint includes composite and inferred state, chunk-match and probe-error state; it excludes raw block coordinates and bracket tick numbers. Output still records the actual raw values at each emitted change or 20-tick heartbeat. This avoids turning a moving reference or advancing clock into a log on every tick, at the cost of leaving intermediate values unobserved. Query exceptions produce unknown fields and `visibility_probe_error=true` when a sample can be emitted; a missing line remains unknown. More queries and records can still affect execution load.

Pure gate, truth-table, timestamp and fingerprint checks are in `tools/tests/test_mutual_visibility_inference.py`; run the Python test suite with Java 17. A separate Gradle build is needed to validate mapped API integration, and any later fixed-version real-MOD GameTest must use a fresh, isolated world and preserve both flags, source/JAR/profile hashes and full logs. Disable the new observer by omitting its property; revert its focused commit to remove the code. Neither action changes existing world force state or cleans up another owner's tickets.

## Optional direct chunk-visibility observation

An additional exact `-PmutualObserveDirectVisibility=true` flag, alongside the ticket and composite flags above, enables a separate read of `ServerLevel.isNaturalSpawningAllowed(frozenBlock)`. In the inspected **Minecraft 1.20.1 / Forge 47.4.20** mapped bytecode, the `BlockPos` overload delegates directly to `PersistentEntitySectionManager.canPositionTick`, which reads the target X/Z chunk's `Visibility.isTicking()` value. The query neither requests a chunk nor changes a ticket. Its name must not be interpreted as a test of every natural-spawn condition or as a guarantee that a particular entity actually ticked.

The probe only calls it after the existing GameTest/scenario/A6M gates, and only if the reported Minecraft/Forge versions exactly match and `level.getClass() == ServerLevel.class`; otherwise direct results are unknown and the output records `unsupported` or `unknown` scope. The inspected Minecraft server creates `ServerLevel` directly, but a different runtime subclass is rejected because it may override the method. An in-place runtime mixin or transformer can still change the implementation without changing the class or reported version, so retain binary hashes and the loaded MOD/transformer inventory with any result. No reported version alone is proof that the inspected bytecode was used.

The direct query uses the same immutable BlockPos and chunk-match guard as the existing composite observer. It follows the existing range/composite pair before the force loop, and separately follows that pair after the loop; no original setter, getter or query is reordered. `direct_before_raw` / `direct_after_raw` are the separate query results, and `direct_before` / `direct_after` are unknown if their start/end game ticks are absent, negative or unequal. A missing reference, different dimension, block/chunk disagreement, unsupported version, query exception or missing log must not be converted to false. A retained reference may be stale; its last-known block remains a location query, not proof of that entity's state. Direct, range and composite reads happen at distinct points; even equal tick labels do not make them atomic, and this position-based state does not demonstrate an entity's scheduler invocation. The existing `*_if_stable` inference remains independently recorded.

`tools/tests/test_mutual_direct_visibility_policy.py` checks the exact opt-in, version/class guard, unknown handling and change fingerprint with Java 17. Run the complete Python suite, then separately build the fixed Forge project; neither compiles nor runs the MOD merely by evaluating the pure tests. A later real-MOD experiment must use a separate fresh world and preserve logs, flags and hashes. The new property is disabled by default; omit it to restore the previous probe's output, or revert its focused commit. Its fingerprint uses state rather than advancing timestamps, so sparse change/heartbeat logging is retained; the direct queries still add diagnostic overhead.

State-change timestamps are first-observed at these END sampling points, not exact engine transition times. The previous fingerprint is one bounded string per validation run; no chunk collection is copied. A scene can finish or disappear before END, or end with an exception or process termination, leaving no final sample. Existing writer buffering and server-log rotation can also hide output. Preserve each run's complete stdout, rotated logs, exit status, code and inputs; never overwrite a prior run. This diagnostic adds no persistent ticket and can be disabled by omitting the property or reverted with its commit. It does **not** change or repair the existing vanilla boolean ownership and cleanup semantics.
