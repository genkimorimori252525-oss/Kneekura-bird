# Player-occupied benchmark stop: natural-tick probe

This experimental test-only probe is intended to observe the retained benchmark session after an occupied stop refusal across actual server END events, while a FakePlayer remains aboard and after that player dismounts. It tests one artificial D4Y scenario, not general benchmark or flight safety. The candidate implementation is experimental, and this natural-tick fixture has not yet been run with the real MOD. A previous synchronous refusal probe cannot establish this scenario's result.

The test uses `benchmarkstopnaturalrespectsplayer`, batch `benchmark_player_stop_natural_probe_only`, template `wwdebug_benchmark_stop_natural_probe:empty` and namespace `wwdebug_benchmark_stop_natural_probe`. `ww-debug-benchmark/tools/benchmark-stop-natural-isolated.init.gradle` selects the namespace and sets `wwdebug.benchmarkStopNaturalProbe=fresh-disposable-world-single-jvm`. This property is an operator attestation, not proof that the world, JVM, players or chunk tickets are isolated. A zero-test run can exit successfully without executing the registration guard: require an explicit record of exactly one matching test, the expected batch and template, all reached-stage markers, test result and process exit. Missing selection or stage evidence is inconclusive.

Before any run, inspect the actual task and canonical paths, reject symlink redirection, confirm a new disposable world and separate JVM with no other players, tests, sessions or chunk-force owners, and independently verify fixed MOD versions and hashes. `prepareFlightGameTestRuntime` modifies the configured `run-gametest` tree; never point it at an existing user world. Preserve the full run directory, world, source revision, inputs and hashes, stdout, stderr and exit status, including on failure or timeout. Do not enable Actions or change runner configuration for this probe.

The setup may seed inputs, phase and position only before the player mounts. Once mounted, the fixture must not write aircraft inputs, engine target, position or velocity; ordinary FakePlayer dismount is a separate operation, with its immediate effects recorded separately from subsequent ticks. Natural physics can change position and velocity between server ticks, and native vehicle logic can change inputs or engine under some conditions. Their equality across different ticks is not a safety requirement or a valid attribution test.

For the same END event, a pre/post comparison can detect a change without crossing a normal world-physics tick only if both observations are present, ordered around the benchmark callback and tied to the same server and tick. Other END listeners, including the autonomous manager, may run in the interval, so a difference is not automatically attributable to the benchmark. Equal values do not exclude same-value writes or temporary changes between observations. Require evidence that the benchmark session actually advanced its elapsed tick; phase retention alone could reflect an unexecuted callback. Entity `tickCount` is evidence of a scheduler visit, not proof that native physics, every subsystem, or a particular input hook ran.

Record identity, occupancy, phase/tick, target control and heartbeat, forced-chunk sets, session elapsed ticks and entity tickCount at the relevant boundaries. Treat missing or ambiguous samples, identity changes, unexpected session removal, unobserved ticks, exceptions and partial setup as inconclusive, not a pass. A forced-set snapshot cannot establish ownership of shared boolean forced chunks or detect intermediate changes.

The asynchronous fixture requires idempotent cleanup for callback errors and timeout, and must check exact session, active object identities and passenger ownership before operating. The GameTest listener and stopping-event cleanup are best effort: a callback failure, missing event, timeout, exception in an earlier listener, process crash or forced termination can prevent cleanup. Never blanket-clear controls or forcibly unforce chunks; if ownership or cleanup is uncertain, preserve the disposable world and evidence. These checks do not establish safe exception abort, shutdown, overlapping ownership, network-player behavior, all aircraft, same-value writes, or completion of Issue #7.

Review `benchmark_stop_natural_probe` records together: the exact selected-test record, `positive_pass`, fuel and sentinel, `pre_stop_phase`, `stop_refusal_pass`, paired `pre`/`post` records for at least three consecutive END events in each of the occupied and dismounted stages, `occupied_natural_pass`, `dismount_pass`, `dismounted_natural_pass`, cleanup with zero failures, `completion_scheduled`, `complete_pass`, the GameTest result and process exit. A first pair establishes a baseline; the two further consecutive pairs establish two scheduler visits. `canUpdate()` is sampled at END only and does not prove what it was during the preceding entity visit. The callback schedules final test completion for a later GameTest tick after cleanup; if it never executes, the test remains inconclusive. A timeout, stopping event, exception or process termination can prevent the callback or cleanup, so missing evidence is not a pass and the world must be retained.
