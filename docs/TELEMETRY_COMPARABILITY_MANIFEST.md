# Read-only telemetry comparability manifest

`ww-debug-benchmark/tools/comparability_manifest.py` inspects exactly one explicit per-aircraft JSONL and one explicit provenance JSON file. It writes a single JSON object to stdout and never discovers, modifies or repairs logs, worlds or profiles. This is a description of recorded evidence, not a flight qualification, safety result, error measurement or Minecraft physics model. The status is always `NOT_COMPARABLE`: main's existing deterministic `FlightSimulationMain` reports aggregate outcomes, not a per-tick trajectory or final applied input trace. Recorded frame controls and `control_adapter` proposals also do not prove the final arbitration winner or setter success. Even a continuous real trace with every hash supplied cannot change that conclusion.

Example with an explicitly prepared provenance file:

```sh
python3 ww-debug-benchmark/tools/comparability_manifest.py \
  --telemetry /absolute/path/to/one-aircraft.jsonl \
  --provenance /absolute/path/to/provenance.json
```

An empty object `{}` is valid provenance when nothing can be established. Allowed keys are `source_head` (40 lowercase hex characters) and `source_sha256`, `mod_sha256`, `immersive_aircraft_sha256`, `warfare_wings_sha256`, `config_sha256`, `profile_sha256`, `model_sha256` (each 64 lowercase hexadecimal characters), with null for unknown. Omitted keys become null. Other fields or invalid types are rejected rather than echoed. Hash values are unverified operator assertions; the tool does not open or associate the referenced source, MOD, config, profile or model, and their correspondence to the telemetry requires separate run evidence. A single `mod_sha256` alone does not identify every runtime MOD. The input byte hashes describe the bytes read, not an independently guaranteed immutable source file or trusted provenance.

The default output includes input file hashes, domain-separated stable hashes of the aircraft UUID, aircraft type and run ID, event counts for a fixed set of public event names, aggregate counts of other events and unlisted fields, known frame-field presence and type-usable counts, and frame tick intervals. It does not echo paths, raw UUIDs, aircraft names, free-text events, reasons, custom field names or values. These hashes are **linkable pseudonyms**, not anonymization or secrets. Run IDs and aircraft types have low entropy and may be inferred by enumerating candidates; UUID hashes and input file digests may also be matched against known data. Review public evidence and its release context before publication. The source telemetry schema has no declared schema version; unknown versions remain unknown. The manifest checks that every row claims the same aircraft UUID, aircraft type and run ID, but this does not prove physical entity continuity or unique sessions. Run/type hashes help distinguish the asserted comparison unit but do not prove its identity or provenance. File order is checked over all rows, and duplicate/decreasing frame ticks are counted. Distinct events can legitimately share a tick; same-tick row ordering and sub-tick motion are not inferred.

Ranges and missing counts cover only gaps *between* the first and last unique observed frame ticks, without expanding large ranges or interpolating. Missing ticks before/after that range are unknown, and an interior gap may reflect sampling, logging failure or other causes; it does not by itself prove corruption. `integrity=VALID` means only that the file passed this tool's limited structural checks: it does not mean complete telemetry, verified provenance, valid model inputs, comparable trajectories or safe flight. Known field presence/usable counts describe JSON shape and finite numeric values, not physical correctness. Unknown fields are counted, not released. Malformed JSON, duplicate object keys, nonfinite numbers, invalid ticks, mixed identities, duplicate or backwards frame ticks, backwards row ticks, and malformed known fields fail closed with `integrity=INVALID` and nonzero exit. Malformed input never yields partial telemetry metrics as if complete. Unknown provenance does not invalidate otherwise readable telemetry, but remains explicitly null and the result remains not comparable.

Both inputs must be strict UTF-8 without a BOM. JSONL rows use LF or CRLF; a bare CR is rejected, while a final line without a terminator is permitted. Inputs must be regular files, not final symlinks or special files, and are limited to 64 MiB, 1 MiB per line excluding its terminator, one million rows and 100,000 contiguous ranges. Lines are read incrementally from the bounded input bytes; no whole-file list of lines is created. Mutations detected while reading cause failure; metadata checks cannot prevent a concurrent writer from changing bytes and restoring metadata. Use a fixed, separately preserved source copy and record the run and environment independently. Existing simulation, logs, validators and safety thresholds are unchanged. A future comparison requires an independently validated model, a per-tick output/input contract, fixed versions, timing/coordinate semantics and measured errors; none are supplied by this tool.
