# Player-occupied benchmark stop refusal probe

This stacked, test-only probe defines a partial protection: when a player controls the single benchmark aircraft, the public `BenchmarkManager.stop` returns `0`, keeps the same session, aircraft, passengers, inputs and forced-chunk set, and clears that aircraft's stored controls and heartbeat. The retained session must remain suspended through synchronous benchmark END calls both while the player remains aboard and after dismount. This specification requires a retained but non-resuming session; it does not prescribe a complete general-purpose stop policy. Production code and the separately selected #145 probe remain unchanged.

The #145 v3 real-MOD run already observed `result=1`, aircraft removal and player dismount on occupied stop. This new fixture has **not** been run on the MOD. It calls the real public `stop` first; it has no refusal shim. Current production is expected to fail at that assertion, so refusal, END and dismount stages are not observed unless earlier stages pass. Distinguish each reached stage explicitly; a later stage cannot be inferred from an earlier result.

Before player mounting, the fixture sets up a real player-free positive-control D4Y session and requires public stop to remove its aircraft and ArmorStand and restore the baseline. It creates a second distinct session, ticks its aircraft once and checks finite positive fuel utilization, establishes a real `CONTROLS` entry and heartbeat via player-free direct benchmark control, and seeds nonzero engine, three input axes, position and velocity. Fuel getters can update synchronized data and are used only before mounting. It seeds `STRAIGHT_ACCELERATION` at `phaseTick=599` before the test, records this phase **before the first END call**, and never reseeds it. After normal FakePlayer mounting it checks the sentinels and then calls public stop. Only a successful refusal with the same session and active test object, both entities and passengers, controls/heartbeat absent, unchanged values and forced set reaches `stop_refusal_pass`.

Two synchronous direct `BenchmarkManager.tick(server)` calls, the method used by the END handler, while occupied and two after ordinary player dismount must retain the original phase and phase tick and the same target session/test and plane, maintain absent controls/heartbeat and preserve the forced set and engine/input/position/velocity snapshots. The immediate dismount state is checked before the first dismounted END call. Explicit per-stage markers identify which checks actually ran. A swallowed benchmark exception can cause abort; any session loss, entity removal, or failed check is failure, not a successful suspension.

## Isolation and evidence

The fixture uses only the dedicated `wwdebug_benchmark_stop_refusal_probe` namespace, `benchmarkstoprefusalsuspendsplayer` test, `benchmark_player_stop_refusal_probe_only` batch and `wwdebug_benchmark_stop_refusal_probe:empty` template, selected by `ww-debug-benchmark/tools/benchmark-stop-refusal-isolated.init.gradle`. Its fresh-world/single-JVM property is an operator attestation, not proof of isolation. Before any future run, independently verify the canonical work directory and absence of symlinks, the new disposable world, fixed MOD input hashes, no other JVM, networked players, tests or chunk owners; `prepareFlightGameTestRuntime` modifies the fixed `run-gametest` tree. Preserve the run world and full stdout, stderr, exit status, source and input provenance, especially on exceptions or partial construction. See [BENCHMARK_PLAYER_STOP_PROBE.md](BENCHMARK_PLAYER_STOP_PROBE.md) for the inherited isolation and cleanup limits.

Zero tests can exit successfully without executing the in-test guard. Valid evidence must include the unique registered-test record; `foreign_identity_refused`, `positive_pass`, fuel and sentinel records, `pre_stop_phase`, `stop_result`, `stop_refusal_pass`, `pre_first_sync_tick_phase`, both numbered `occupied_sync_tick_pass` records, `dismount_pass`, both numbered `dismounted_sync_tick_pass` records, `player_pass`, cleanup result, GameTest outcome and process exit. Missing markers mean the corresponding stage is unverified. Cleanup dismounts only the fixture FakePlayer, checks session ownership and no remaining player before aborting known test objects, and compares the 25 initial GameTest forced chunks. Failed or unknown ownership/state must not be guessed or blanket-unforced; preserve the world.

These direct calls do not dispatch actual `ServerTickEvent.END` events, advance game time, or interleave the other events of natural ticks. These synchronous single-aircraft calls do not prove safety for other aircraft, exception-driven abort, shutdown, overlapping chunk owners, same-value writes, attitude, fuel changes, a networked player, concurrent calls, or natural entity/world ticks. A set comparison does not establish ownership or exclude changes between snapshots. Snapshot equality and phase retention do not prove all side effects absent. This fixture neither changes thresholds nor establishes issue #7 completion.
